# 10 · 数据查询 API

PRD 1.0 · 2026-10-18 · 付费数据服务 · 先落实数据与用户  
状态：设计提案，未实现/未付款/未提交。先读[总体接入设计](../总体接入设计.md)与[接口事件约定](../接口与事件约定.md)。

## 1. 用户与真实场景

**用户：**拥有可提供数据的开发者/机构，以及按任务需要查询数据的 Agent。

**第一次使用：**Agent 要查询某个地区的公开设施信息或授权产品数据，不需要买整库；通过一个参数明确的接口购买可追溯时点的查询结果。

**问题：**数据来源、许可、时点与更新质量不清，买方还需要分别处理订阅和密钥；泛化 SQL 开放又有越权和高成本风险。

**Kite 接入价值：**Kite 提供 Agent 发现和按次采购通道；项目价值来自真实有用、可持续提供且有使用权的数据。没有数据优势时不为了开仓造一份演示数据库。

## 2. MVP 范围

**P0，首版必须完成：**

- 只选一个有真实买方的数据集；记录来源、使用许可、更新时间及字段说明。
- 提供固定参数化查询与明确的分页上限，不接受任意 SQL。
- 价格绑定查询规格和数据版本，返回结果的 as_of、来源和行数/截断说明。
- 使用自己的卖方凭证连接数据源，原始数据库密钥不交给买方；按用户权限限制字段与行。

**P1，有真实反馈后再做：**

- 有付费需求后增加一个查询类别或刷新周期；不同数据源单独核验许可。
- 支持已购快照重复访问和版本差异，复用对账与商家工具。

**首版排除：**不抓取和转售无权数据、不开放任意 SQL、不编造数据优势、不承诺全网实时。

## 3. 完整用户流程

1. 维护者登记数据来源与使用条件，创建经过验证的数据版本。
2. Agent 发现端点，读取字段、参数、价格和可运行样例。
3. 服务预检参数与访问权限，锁定查询规格和数据版本。
4. 用户通过 Passport 批准会话并付费执行。
5. 只读查询完成、结果符合规格后结算，返回来源和时点。
6. 请求恢复时读取同一已购结果；换页/换版本是否收费按明确端点规则，不隐式再次采购。

## 4. Kite 能力接入

| 官方能力 | 接入方式 | 保存与验证 |
|---|---|---|
| 采购 | ksearch + Passport delegation/execute | 按真实示例查询，端点授权与报价匹配 |
| 卖方结算 | x402 验证→只读查询→有效结果→结算 | 数据源不可用不先收费，源站 stale 不冒充新数据 |
| 目录 | 闭合 service.yaml | 真实例子、来源条款、字段说明、分页和收费 pitfalls |

**接入前置：**所有涉及真实付款的路径先完成 G0，固定 network/asset/facilitator/CLI/账户环境；见总体接入设计。真实身份或 Runtime 不可得时明确 blocked，不能用 mock 替代。

**授权边界：**应用与业务权限自己验证；Passport 的 passkey 批准保留给真实用户；本轮 PRD 编制不发起任何授权或支付。协议实例、金额、会话和示例均以现场预检与实际输出为准。

## 5. 接口与数据

**拟提供接口：**POST /v1/data/query 输入 {operation_id,dataset_version,query_type,filters,limit}；输出 {query_id,dataset_version,as_of,source,license_summary,rows,truncated,next_cursor?}。首版一页固定规格，分页单独端点与报价，不自动循环收费。

**核心对象：**Dataset、SourceTermsVersion、DatasetVersion、QueryTemplate、QuerySpec、QueryResult、Entitlement、Purchase。条款版本、数据时点与计费版本独立保存。

operation_id、付款证据、业务版本及产物按公共事件契约关联。接口/包名属于本项目设计，不代表官方已经发布同名能力。

## 6. 状态与恢复

SOURCE_APPROVED → SNAPSHOT_READY → QUERY_VALIDATED → PAYMENT_VERIFIED → QUERY_COMPLETED → SETTLED → DELIVERED；另有 stale、source_failed、permission_denied、payment_unknown。

- 查询注入、超范围字段、超大 limit 在收费前阻止；只读数据库账号和资源上限。
- 合法的零行结果按已声明查询合同可收费；查询执行失败不能冒充零行正常结果。
- 来源许可改变就暂停受影响服务；结算成功不自动授予用户再分发权。

任何付款未知均不能通过换 key 自动重买；任何产物恢复都需要原权限。测试桩中的假付款不产生真实交付承诺。

## 7. 开发任务拆分

- 10-T01：访谈一个真实买方并落实数据权利，不满足则不立项。
- 10-T02：定义参数化查询、版本与结果合同。
- 10-T03：实现只读访问、权限和资源约束。
- 10-T04：实现支付、产物保存和来源说明。
- 10-T05：完成真实调用与更新故障验证。

**投入粗估：**4–6 人周，不含数据供应谈判。先做 M0 兼容与样本验证，再做独立核心、真实互通及发布；外部批准、环境开通和审核不计入可承诺工期。

## 8. 界面与使用体验

面向 API，辅助查询页展示参数、价格、数据时间和结果；不先做泛数据市场。

在需要用户决定时展示价格、范围、权限和失败状态；普通产品页面不堆协议实现细节，技术证据留在诊断/报告页。

## 9. 验收与演示

下面是目标，尚未运行或达成。

- Q01：至少一个许可明确、真实有用的数据源和两个有标注预期的查询案例。
- Q02：来源/时点/截断/分页和零行收费语义完整，更新失败不会刷新 as_of。
- Q03：越权字段、参数注入、超限、数据源故障和付款未知处理可复现。
- Q04：一笔真实 Passport 查询与产物版本可对应，返回字段和 manifest example 一致。

**完整演示：**购买一个固定版本查询，核对数据来源和时点；断开上游，验证错误不会被包装成成功空结果。

**试用观察：**有实际用途的重复查询、结果新鲜度、查询成本、数据错误反馈与真实买方留存。

## 10. 提交与独立性

x402 付费服务方向较直接；上游条款、例子和真实付款证据需完整。数据权利与协议验证分别验收。

项目核心包括本 PRD 定义的模型、业务引擎/状态/断言与样本；支付和基础依赖可正常共享，不复制其他参赛实现换名。EC 映射、活动审核与真实贡献是否被统计分别跟踪，不用本 PRD 保证收录。
